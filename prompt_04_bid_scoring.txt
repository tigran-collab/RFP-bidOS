The frontend is connected to the backend and displays demo opportunities. Implement rules-based bid/no-bid scoring only.

Goal:
Add a deterministic scoring engine that scores an opportunity and updates the Opportunity record with bid_decision, bid_score, and bid_reason.

Do not implement scraper functionality yet.
Do not implement LLM features yet.
Do not implement file downloading yet.
Do not change frontend layout beyond adding a simple score button/display if needed.

Backend requirements:

1. Create or update backend/app/services/scorer.py.

Implement function:

score_opportunity_text(opportunity) -> dict

The function should inspect available opportunity fields:
- title
- agency
- source
- source_url
- location
- due_date
- pre_bid_date
- pre_bid_mandatory
- q_and_a_deadline
- service_type
- contract_type
- estimated_value
- status

Return:
{
  "score": int,
  "decision": string,
  "reason": string,
  "positive_factors": list[str],
  "negative_factors": list[str],
  "verification_needed": list[str]
}

Scoring rules:

Positive:
- Security services match: +30
- Armed/unarmed/patrol/facility/courthouse/healthcare security: +15
- Location in CA/TX/NV/AZ: +15
- Due date found: +10
- Required licenses appear aligned with BSIS/PPO/Guard Card: +15
- Guard Owl fit: +10
- Public agency or multi-site real scope: +10

Negative:
- As-needed/on-call/standby/no guaranteed minimum: -40
- Mandatory pre-bid missed or possibly missed: -100
- Required license not held or unclear: -75
- Due date missing: -20
- Due date too close: -25
- Heavy proposal with low value: -25
- Excessive bonding/insurance: -30
- Unclear scope or unclear volume: -20
- Non-security opportunity: -50

Decision bands:
- 70+ = Bid
- 45–69 = Conditional Bid
- 0–44 = Usually No Bid
- Below 0 = No Bid
- Any disqualifier = No Bid

Important user preference:
Do not recommend purely as-needed, on-call, standby, or no-guaranteed-minimum contracts as strong pursuits unless there is a guaranteed minimum, clear strategic value, high likelihood of use, or very low response burden.

The reason string should be short and direct.

2. Add API route:

POST /opportunities/{id}/score

This should:
- load the opportunity
- run the scorer
- update bid_score
- update bid_decision
- update bid_reason
- return the scoring result and updated opportunity

3. Add CLI command:

python -m app.cli score-opportunity <id>

This should:
- score one opportunity
- print score, decision, and reason

4. Add CLI command:

python -m app.cli score-all-opportunities

This should:
- score every opportunity in the database
- print each title, decision, and score

5. Frontend:
On OpportunityDetail page:
- Add a button: Run Bid/No-Bid Score
- On click, call POST /opportunities/{id}/score
- Refresh/display bid decision, score, and reason

On Opportunities table:
- Display bid decision and bid score if available.

6. README:
Add scoring commands:
python -m app.cli score-opportunity 1
python -m app.cli score-all-opportunities
