The app currently has PDF text extraction implemented with PyMuPDF/fitz, but the Windows local environment has a native DLL load issue with PyMuPDF. Replace or supplement the PDF parser with pypdf so PDF text extraction works without native DLL dependency issues.

Goal:
Make PDF parsing reliable on Windows by using pypdf as the primary parser, or as a fallback when PyMuPDF fails.

Do not remove the existing parser API, CLI commands, database fields, or frontend behavior.
Do not add OCR.
Do not add cloud services.
Do not add OpenAI API.
Do not add Playwright.
Do not add recursive crawling.
Do not add proposal drafting.
Do not run uvicorn --reload as an automated check.

Requirements:

1. Add pypdf dependency

Update requirements.txt to include:

pypdf

If PyMuPDF is currently in requirements.txt, keep it only if needed, but make sure the app does not require PyMuPDF to start or to parse PDFs successfully.

2. Update parser service

Find the current PDF parsing service.

Implement parsing order:

- Try pypdf first.
- If pypdf fails, optionally try PyMuPDF only if available.
- If both fail, mark the document as Parse Failed and store a clear parse_error.

pypdf extraction behavior:

- Open the PDF file.
- Iterate pages in order.
- Extract page text using pypdf.
- Add page separators in the output:

--- Page 1 ---
[text]

--- Page 2 ---
[text]

- Save extracted text to:

data/processed/opportunity_<opportunity_id>/document_<document_id>.txt

3. Make PyMuPDF truly optional

The backend must start even if PyMuPDF is not installed or cannot load DLLs.

Do not import fitz at module import time.

Only import fitz inside a fallback function, inside try/except.

If fitz import fails, continue to pypdf behavior or return a clean parse failure.

4. Keep existing commands working

These existing CLI commands must still work:

python -m app.cli parse-document <document_id>
python -m app.cli parse-opportunity-documents <opportunity_id>
python -m app.cli parse-all-documents

5. Keep existing API working

These routes must still work:

POST /documents/{id}/parse
POST /opportunities/{id}/parse-documents
POST /documents/parse-all

6. Improve parse result messages

When parsing succeeds, include:

- parser_used: "pypdf" or "pymupdf"
- page_count
- extracted_text_path
- parsed_status: "Parsed"

When parsing fails, include:

- parsed_status: "Parse Failed"
- parse_error with useful detail
- do not crash backend

7. README update

Update README with:

- pypdf is the default parser
- PyMuPDF is optional
- OCR is not supported yet
- scanned/image-only PDFs may produce little or no text

8. Verification commands

Run:

python -m pip install -r requirements.txt
python -m app.cli init-db
python -m app.cli seed-demo
python -m app.cli parse-all-documents
python -m app.cli ai-evaluate-all-opportunities
npm.cmd run build

Do not run uvicorn --reload as a long-running automated verification command.
